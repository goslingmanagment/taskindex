# Приёмка агентского цикла

Использовать отдельную тестовую базу, URL и два ключа разных агентов со scope write.
Зафиксировать сборку, generation и идентификаторы операций. Проверить один и тот
же сценарий из настоящих сессий Claude Code и Codex; не считать эту инструкцию
отчётом о выполненной проверке. Production не использовать.

1. Оба агента читают context и digest. Первый создаёт проект с описанием. Второй
   находит его через context, затем оба вызывают sync с одинаковым origin и
   настоящей версией источника. На экране после SSE одна задача, автор определён
   ключом, оба получают объяснимый результат. Отдельно проверить источник без
   версии: первый sync создаёт, следующий даёт freshness_unknown без записи.
2. Владелец в браузере переносит задачу в другой проект и закрывает. Агент
   синхронизирует более новую версию источника: закрытый статус и выбранный
   проект сохраняются; skipped объясняет результат. Оба агента добавляют
   комментарии одновременно с сохранением заметки владельцем — ничего не теряется.
3. Владелец открывает карточку и набирает текст. Агент меняет другое поле: запись
   через SSE обновляется, черновик остаётся. Затем оба меняют одно поле: сохранить
   устаревший вариант должно вернуть conflict/current и сохранить текст формы.
4. Агент создаёт batch из нескольких задач. Активность показывает одну операцию.
   Владелец отменяет её целиком, затем проверяет защиту от отмены после поздней
   правки затронутого поля. Ключ tasks не может отменить project.update.
5. Прокси тестового окружения принимает POST /api/commands, передаёт его серверу,
   затем разрывает ответ после commit. Зафиксировать operationId из CLI outbox.
   `operation get ID` возвращает сохранённый результат, `operation resume ID`
   ничего не дублирует. Не заменять этот сценарий отказом сети до отправки.
6. Запустить новый deployment ID с writes:held. CLI делает четыре попытки с
   одинаковым конвертом, сохраняет его после 503 и выходит с кодом 1. Выполнить
   admin open-writes, затем operation resume — ровно одно изменение. Перезапуск
   того же deployment оставляет writes:open; следующий deployment стартует held.
7. Перезагрузить вкладку с неподтверждённой отправкой и черновиком, проверить
   выяснение операции без нового ID. В отдельной восстановленной базе выполнить
   mark-restored: старые конверты не отправляются под новым generation, тексты
   черновиков доступны для ручного переноса.

Результат записать отдельно: кто выполнял, URL тестового окружения, build,
generation, operationId каждого существенного шага, ответы и снимки экрана,
пройденные шаги и точная причина непройденных. Секреты не включать.
