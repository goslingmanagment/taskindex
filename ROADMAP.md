## 1. Код TaskIndex

Три поля задачи: приоритет P1–P3 (по умолчанию P2, Someday это P3), метки из
каталога в коде (`ответ`, `деньги`, `5 мин`, `lora`, `lily`, `ari`), `closes` со
слагом проблемы из `/OS/PROBLEMS.md`. Значок и чипы на карточке, поля в
редакторе, пункты меню, галочка «Без P3» в предпочтении владельца. Фильтры в
CLI и API. Порядок карточек остаётся ручным, приоритет не сортирует.

Готово, когда: `npm run check` и `npm run e2e` зелёные, миграция прошла на копии
`data/dev.db`, карточка TI-086 закрыта. Коммит и деплой по слову владельца;
в день выпуска открытые вкладки перезагрузить до первой записи.

## 2. Скилл и сценарий

Один файл `skills/taskindex/SKILL.md`: правило записи первым разделом (любая
запись только по просьбе владельца в этом чате, всегда в два шага: показать
карточку или изменение, дождаться отдельного «да»; «иди создай» это просьба, не
подтверждение), потом что куда (области, направления, приоритеты, метки,
`closes`), как отвечать на «что горит», техника вниз. Установка симлинком в
`~/.claude/skills` и `~/.codex/skills`, ключ `codex-mac`. Одна строка в
`~/code/AGENTS.md` про задачи по коду.

Готово, когда: сквозной сценарий спеки §1.1 пройден в sandbox из Claude Code и
из Codex.

## 3. /OS: правило и генерация `TASKS.md`

В `/OS/CLAUDE.md` пункт «Задачи» меняется: задачи ведутся в TaskIndex,
`TASKS.md` пишет скрипт `scripts/render_tasks_md.py`, руками не правится. В файл
попадает только область «Агентство»: секции Active, Waiting On, Someday (это
P3), Done без `closes`; теги `[ответ] [деньги] [5 мин] [найм] [сегодня]` из
меток, направления и срока. Свежесть: читатели рендерят перед чтением
(`weekly-os-audit`, Пульт задач), launchd раз в час коммитит при изменениях.
Завершение задачи с `closes`: проблему снимает только сессия /OS по слову
владельца.

Готово, когда: сгенерированный файл проходит `scripts/validate.sh`, Пульт задач
открывается, launchd отработал хотя бы раз.

## 4. Направления и перенос задач

Шесть направлений агентства одним пакетом: Найм, Контент, Чаттеры, Трафик,
Финансы, Организационное. Разработка: одно направление на репозиторий, заводится
вместе с первой задачей. Личное без направлений. Перенос `TASKS.md`: агент
показывает таблицу «строка → направление, приоритет, метки», владелец говорит
«да», потом сам расставляет P1 и порядок. Задачи с `[код]` уезжают в
«Разработку» и в файл не возвращаются.

Готово, когда: `render_tasks_md.py` воспроизводит прежний файл с точностью до
порядка и ушедших строк `[код]`. С этого момента доска используется каждый
день.

## 5. winpc и Бобр

winpc: Node 26, пакет CLI из `npm pack`, скилл копией, ключи `claude-winpc` и
`codex-winpc`. Бобр (OpenClaw): CLI на маке, ключ `openclaw` со scope `tasks`
через плагин 1Password, скилл через `openclaw skills install`; в крон-сессиях к
TaskIndex не обращается. Рутины (`hiring-daily`, `customs-daily`,
`traffic-daily`, `weekly-os-audit`, `bybit-nightly`) ключей не получают.

Готово, когда: сценарий §1.1 пройден в каждой среде, установка описана
пошагово в README.

## 6. MCP с OAuth для чатов

Один удалённый MCP на VPS за Nginx с OAuth 2.1: Claude.ai, приложение Claude на
телефоне и компьютере, коннектор ChatGPT. Каждый клиент получает свою
идентичность агента (`claude-chat`, `chatgpt-chat`). Отдельная спека и план.

Готово, когда: из приложения Claude на телефоне задача создаётся по тому же
правилу «карточка, „да“, запись».
