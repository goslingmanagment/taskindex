## Воспроизведение

Из корня v2 worktree с Node 24 и установленными зависимостями:

```sh
npm run e2e
```

Конфигурация: `tests/e2e/playwright.config.ts`. Сервер тестов создаёт отдельную
SQLite-базу в `/tmp/taskindex-e2e-*`, мигрирует её и создаёт тестового владельца
штатным admin API. Вход проходит через настоящий Better Auth. API слушает
localhost:4001, Vite — localhost:4173. Данные из
`tests/e2e/reference-data.json` создаются только через реальные команды API.
Это копия тестовой фикстуры эталона: 10 направлений и 20 задач, включая
архивную. Предыдущие сценарии также оставляют свои тестовые операции в ленте.
Время приложения не подменяется: календарные подписи меняются с датой запуска.

Production v2 стартует с пустой базы. Фикстур и seed-инициализации в
production-коде нет. Legacy сервер, D1 и `.wrangler/state` не используются.

## Проверенные сценарии

Восемь Playwright-сценариев проходят на реальном API и SQLite:

1. Вход по паролю, создание, атомарный `task.save` только изменённых полей,
   комментарий и история.
2. Конкурирующее изменение через API, конфликт в редакторе, сохранение
   собственного текста и восстановление черновика после reload.
3. `N`, `Cmd+K`, клавиатурный перенос в пустую колонку, мобильный sidebar,
   Focus, поиск и архив.
4. Сервер завершает команду, HTTP-ответ теряется и SSE заблокирован;
   reload восстанавливает сохранённый конверт по operationId без дубля задачи.
5. Заполненный интерфейс и снимки по исходной фикстуре.
6. Реальный mouse drag и CDP touch-emulation drag с проверкой статуса задачи
   через API. Используются dnd-kit MouseSensor, TouchSensor, KeyboardSensor
   и DragOverlay с тем же содержимым карточки.
7. Сохранённый terminal 404 виден в Activity как отказ с русской причиной,
   детали открываются без ошибки загрузки, Undo недоступен.
8. Регистрация passkey, выход, подтверждение отсутствующей сессии и повторный
   вход с passkey. Использован CDP virtual WebAuthn authenticator: CTAP2,
   internal transport, resident key, user verification; rpId `localhost`.

13 Vitest-проверок в `tests/web` покрывают целостное применение batch ACK,
разрывы seq и страницы catch-up, no-event ACK, повторяемый 503, конфликты,
reload и смену generation, стабильность optimistic id/времени, lazy-счётчик
комментариев, dirty-fields `task.save`, различие отказа операции и ошибки
загрузки её сохранённого результата.

Физический телефон, Safari, системный passkey/Touch ID и внешнее устройство
ещё не проверены. Удобство новых Activity/comments/history требует отдельного
просмотра владельцем. Deploy и переключение production этой проверкой не
выполнялись.
