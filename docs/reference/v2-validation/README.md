## Воспроизведение

Из корня v2 worktree с Node 24 и установленными зависимостями:

```sh
npm run e2e                     # все проекты, ничего не меняет в docs/
npm run e2e -- --project visual # только эталонные сцены
npm run e2e:publish-reference   # переснять эталон в этой папке
```

Обычный прогон пишет снимки, `environment.json` и `screenshots-sha256.json` в
`test-results/e2e-artifacts/` (каталог в `.gitignore`) и ничего не меняет в
`docs/`. Снимки в этой папке — зафиксированный эталон; обновляется он только
осознанно, явной командой `npm run e2e:publish-reference`. Она запускает проект
`visual` с `TASKINDEX_E2E_ARTIFACT_DIR=docs/reference/v2-validation`; без этой
переменной сюда не пишет ничего. После такого прогона снимки просматривают
глазами, обновляют дату в заголовке этого README по `capturedAt` из
`environment.json` и коммитят всё вместе. Умолчание и переменная описаны в
`tests/e2e/artifacts.ts`.

TI-070: все восемь снимков воспроизводимы побайтно. Проект `visual` работает на
собственной чистой базе, поэтому в кадр не попадают записи других сцен, а часы
заморожены с двух сторон — сервер получает `now` из `TASKINDEX_E2E_NOW`
(`tests/e2e/server.ts` → `createApp`), браузер — через `page.clock.setFixedTime`
с тем же моментом `2026-09-08T09:00:00.000Z`. Из-за этого «Сегодня», «Завтра» и
метки времени в ленте и обсуждении больше не зависят от даты запуска. Проверка:
два прогона `npm run e2e -- --project visual` подряд дают одинаковый
`screenshots-sha256.json`. Меняется между прогонами только `environment.json`
(поле `capturedAt` и версия браузера) — это запись о прогоне, а не кадр.

Конфигурация: `tests/e2e/playwright.config.ts`. Каждый проект поднимает свой
сервер тестов: отдельная SQLite-база в `/tmp/taskindex-e2e-*`, миграции,
владелец через штатный admin API, вход через настоящий Better Auth. Проект
`setup` записывает сессию владельца в `test-results/e2e-auth/<база>.json`, и
остальные проекты стартуют уже с ней. Базовый проект `functional` слушает
localhost:4001 и localhost:4173, `visual` — 4002/4174, `dark` — 4003/4175,
`webkit` — 4004/4176, `webkit-dark` — 4005/4177. Проект `static`
(`tests/e2e/static.spec.ts`, TI-069) отдельно поднимает production-сборку
`vite build` через настоящий `src/server/index.ts` на localhost:4373 и проверяет
вход, `Cache-Control` статики и заголовки. Проекты `webkit` и `webkit-dark`
(TI-018) требуют `npx playwright install webkit`.

Данные из `tests/e2e/reference-data.json` создаются только через реальные
команды API. Это копия тестовой фикстуры эталона: 10 направлений и 20 задач,
включая архивную. Никаких записей других спек в кадре больше нет.

Production v2 стартует с пустой базы. Фикстур и seed-инициализации в
production-коде нет. Legacy сервер, D1 и `.wrangler/state` не используются.

## Проверенные сценарии

Сценарии проходят на реальном API и SQLite. Проект `functional` (если не
сказано иное), снимки — проект `visual`:

1. Вход по паролю, создание, атомарный `task.save` только изменённых полей,
   комментарий и история.
2. Конкурирующее изменение через API, конфликт в редакторе, сохранение
   собственного текста и восстановление черновика после reload.
3. `N`, `Cmd+K`, клавиатурный перенос в пустую колонку, мобильный sidebar,
   Focus, поиск и архив.
4. Сервер завершает команду, HTTP-ответ теряется и SSE заблокирован;
   reload восстанавливает сохранённый конверт по operationId без дубля задачи.
5. Заполненный интерфейс и восемь снимков по исходной фикстуре, включая
   отклонённую операцию (проект `visual`, `tests/e2e/visual.spec.ts`).
6. Реальный mouse drag и CDP touch-emulation drag с проверкой статуса задачи
   через API. Используются dnd-kit MouseSensor, TouchSensor, KeyboardSensor
   и DragOverlay с тем же содержимым карточки.
7. Сохранённый terminal 404 виден в Activity как отказ с русской причиной,
   детали открываются без ошибки загрузки, Undo недоступен.
8. Регистрация passkey, выход, подтверждение отсутствующей сессии и повторный
   вход с passkey. Использован CDP virtual WebAuthn authenticator: CTAP2,
   internal transport, resident key, user verification; rpId `localhost`.

13 Vitest-проверок в `tests/web` покрывают целостное применение batch ACK,
разрывы seq и страницы catch-up, no-event ACK, повторяемый 503, конфликты,
reload и смену generation, стабильность optimistic id/времени, lazy-счётчик
комментариев, dirty-fields `task.save`, различие отказа операции и ошибки
загрузки её сохранённого результата.

Движок WebKit покрыт проектами `webkit` и `webkit-dark`
(`tests/e2e/webkit.spec.ts`): вход по паролю и выход, создание, правка и
сохранение с переподключением SSE, восстановление черновика после перезагрузки
(Web Locks), чеклист, комментарии, индикатор неподтверждённой команды, доска,
редактор и лента в тёмной теме. Физический телефон, Safari на iPhone, системный
passkey/Touch ID и внешнее устройство ещё не проверены — чек-лист устройства в
[docs/acceptance/phone.md](../../acceptance/phone.md).

Удобство новых Activity/comments/history требует отдельного просмотра
владельцем. Deploy и переключение production этой проверкой не выполнялись.
