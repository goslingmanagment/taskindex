**Все шесть подтверждённых багов B01–B06 исправлены в рабочем дереве.** Финальная проверка: 75/75 тестов, 18/18 E2E, TypeScript, lint, форматирование и production-сборка проходят. Проверялось на Node 24.20.0 с отдельными тестовыми базами.

| Баг                                              | Итоговое поведение                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B01 — потеря черновика другой вкладки            | Каждая вкладка владеет отдельным набором черновиков в localStorage. sessionStorage сохраняет выбор набора, Web Lock исключает двух писателей в одном наборе. Дублированная вкладка получает независимую копию; перезагрузка сохраняет текст, закрытый набор можно восстановить. Старые ключи читаются совместимо. |
| B02 — возвращается стёртый комментарий           | Явное очищение поля удаляет черновик этой вкладки.                                                                                                                                                                                                                                                                |
| B03 — повторно предлагается уже созданная задача | Обе формы создания получают изменения общего для них черновика, включая его использование. Сбрасываются текст и идентификаторы запроса; проверены закрытая и оставшаяся открытой встроенная форма.                                                                                                                |
| B04 — повторный конфликт проекта                 | Форма хранит базовую запись и конфликтующую версию. Показывает актуальные поля и предлагает «Совместить и проверить». Неизменённые поля берутся из актуальной записи; свои правки сохраняются. Закрытие формы не обходит сравнение.                                                                               |
| B05 — актуальная версия за экраном телефона      | Действия футера и блок конфликта имеют отдельную раскладку. Блок укладывается по ширине и прокручивается; проверены раскрытие актуальной версии, совмещение и успешное сохранение на 320×568. Диалог конфликта проекта также ограничен высотой экрана.                                                            |
| B06 — устаревшая активность                      | Сервер отправляет отдельное SSE-уведомление после записи операции, включая отказ и успешную операцию без доменных событий. Повторы и dry run не создают лишнего сигнала. Подключение восстанавливает актуальность ленты; обновление сохраняет глубину загруженных страниц и отбрасывает устаревшие ответы.        |

Уведомление об операциях не меняет `Last-Event-ID` и не подменяет доменный журнал. Изменения схемы базы для исправлений не нужны. При отсутствии Web Locks создаётся отдельная копия черновиков с сохранением исходных записей; основная браузерная проверка выполнена с поддержкой Web Locks.
