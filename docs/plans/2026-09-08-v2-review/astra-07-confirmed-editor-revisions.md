## Причина и наблюдаемое поведение

Pending-перемещение рисует optimistic revision=2. Открытый следом редактор использует её как серверную базу и может отправить save раньше move. Сервер правомерно отклоняет версию из будущего. Подтверждён отказ сохранения, а не безусловная потеря текста.

## Что изменится и зачем

UI-проекция остаётся быстрой, но optimistic revision никогда не выдаётся за подтверждённую базу следующей операции.

## Шаги реализации

1. Сделать API store для чтения confirmed entity и списка pending, затрагивающих её. UI-данные и база редактирования должны быть различимы в типах и параметрах.
2. Для первой реализации разрешать ввод в редакторе при pending, но блокировать зависимый submit с понятным состоянием до известного исхода предыдущей операции.
3. После success обновлять базу по confirmed и выполнять существующее разрешение изменений полей. После rejection сохранять draft и показывать фактическое состояние, после unknown не предполагать success.
4. Проверить create→edit, move→save, checklist→save, комментарии с отдельной revision и пакетные команды. Блокировать только действительно связанные сущности, а не всю доску.
5. Если позже нужен автоматический queue, хранить намерение и зависимости, строить envelope после подтверждения предыдущей операции. Простая последовательная отправка заранее построенных envelope не исправляет базу после отказа.
6. Согласовать lifecycle редактора с общим механизмом из плана 23 без потери различий между конфликтом предметных полей и ожиданием pending.

## Проверки

- [ ] Управляемая доставка move/save в обратном порядке: второй запрос не уходит с будущей revision.
- [ ] Первая операция success/rejection/unknown, серверная параллельная правка, закрытие/открытие редактора и reload — текст не исчезает и результат не выдумывается.
- [ ] Правка другой задачи остаётся доступной; отдельная revision комментария не блокируется необоснованно.

## Критерий готовности

Исходный probe закрыт; все bases происходят из confirmed; для неизвестного результата зависимое действие имеет явный статус.
