## Причина и наблюдаемое поведение

Нужные проверки существуют, но в репозитории нет обязательного CI-gate, а build/deploy не доказывает запуск typecheck, lint и тестов для именно этого image. Успешная транспиляция может пропустить ошибки типов и поведения.

## Что изменится и зачем

До остановки работающего выпуска есть проверяемый результат тестов, связанный с точным commit и image digest.

## Шаги реализации

1. Описать минимальный gate: Node 24, npm ci по lockfile, npm run check, npm run build, релевантный browser suite. Native SQLite должен собираться под согласованный ABI.
2. Реализовать CI выбранного git-host либо локальный preflight с теми же командами, если CI ещё не настроен. Решение не должно требовать отдельного облачного сервиса ради галочки.
3. Привязать результат к immutable commit/tree и digest image. Dirty working tree не должно выдавать чужой зелёный check за проверку своих изменений.
4. Проверку выполнить до остановки сервиса и изменения рабочей БД. Failed gate запрещает продолжение выпуска, но не запускает сам deploy.
5. Определить тестовые артефакты и безопасные имена/каталоги. Обычный E2E не перезаписывает принятые reference screenshots; fixture/env изолированы.
6. Добавить правила расширения gate: миграции требуют историческую DB fixture, deploy-изменения — isolated drill, темы — соответствующую визуальную матрицу.

## Проверки

- [ ] Преднамеренная ошибка типов/теста останавливает gate до stop/migrate.
- [ ] Проверка commit A не разрешает image B; сохранённый отчёт содержит версии инструментов и digest.
- [ ] Чистый checkout на Node 24 воспроизводит gate без локальных /tmp-настроек и production-секретов.

## Критерий готовности

Есть один задокументированный воспроизводимый вход проверки и невозможность случайно засчитать чужой выпуск; автоматического деплоя от добавления CI нет.

## Зависимости и границы

Жёстких зависимостей от других планов нет; работать от актуального snapshot исходников.

Не требовать все дорогие проверки для каждого документационного изменения. Минимальный suite обязателен для кода, дополнительные проверки выбираются по затронутым гарантиям.
