### Расхождения и как они разрешены

1. **«Критичных и высоких багов нет».** Наш вывод относился к нашему набору. В объединённом списке два дефекта доступа и изоляции заслуживают P1: отзыв ключа не закрывает SSE (Astra) и общий outbox агентов (мы). Формулировку снимаем.
2. **Тяжесть Astra B-01.** Дефект реален, но поставляемый CLI не открывает SSE, а опрашивает `/api/events` раз в секунду, поэтому для сегодняшних клиентов окно закрывается на следующем запросе. Остаётся P0 до раздачи ключей за пределы машины владельца, и его нужно проектировать вместе с нашим предложением по проверке ключа: кэш результата `verifyApiKey` расширил бы то же окно.
3. **Права агентов.** Мы называем отмену операций владельца агентом дефектом, Astra считает вопрос открытой политикой. Факт поведения совпадает; текст правил в `/api/context` обещает сохранение ручных решений при undo, что сегодня не выполняется. Решение за владельцем: единая матрица прав в плане 02 и `astra-27`, а не точечный запрет одного undo.
4. **Внутренние ошибки как окончательные.** Наше предложение отвечать `retryable: false` на любой не-SQLite `Error` Astra отвергла обоснованно: ошибка после коммита при рассылке или формировании ответа сделала бы успешную операцию «провалом» для клиента. Граница проходит по известности результата, а не по классу исключения. План 06 исправлен.
5. **Пагинация.** Наш keyset по `(orderKey, id)` сам по себе не даёт полного согласованного обхода, потому что `orderKey` изменяемый. Нужна семантика по видам лент: монотонная позиция для журнала, оговорённый snapshot или распознаваемое изменение с повтором для списка задач. План 01 уточнён.
6. **Плагин api-key.** Astra рекомендовала оставить, не проверив стоимость; после нашего замера согласилась пересмотреть путь проверки ключа, но не принимать «своя таблица за 30–50 строк» без списка требований: хеширование, ротация, отзыв, отключение агента, миграция выданных ключей, долгоживущие соединения. План 05 содержит этот список.
7. **OpenAPI.** Наши отчёты противоречили друг другу: review-1 предлагал убрать, review-5 сделать удобным для агента. Принято второе. Публичность документа без ключа не обязательна, достаточно компактной схемы для аутентифицированного CLI.
8. **Клиентская валидация и вес бандла.** Вариант «валидация только на сервере» из review-1 снят: проверка snapshot, событий SSE и ответов операций на клиенте нужна, вес снимается переходом `src/shared` на `zod/mini`.
9. **Наша ошибка.** Review-2 V7 приписал `/health` постоянные записи в WAL. Три независимых замера, наших и Astra, дали 0 байт: SQLite не фиксирует страницу с побайтно тем же содержимым. Снято, в реестре TI-075.
10. **Drizzle.** Мы допускали уход на raw SQL или `node:sqlite`, Astra предлагает сначала починить выборки на текущем стеке и измерить. Принято как порядок: сначала выборки, замена только по результату замера.

## Порядок выполнения
