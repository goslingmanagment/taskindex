## Причина и наблюдаемое поведение

Таблицы, события и сохранённые command-result имеют строгие схемы, а импорт сверяет replay с текущими записями. Для следующей доменной миграции недостаточно ALTER TABLE. Старый открытый клиент и прежний outbox тоже продолжают существовать. Аудит не доказал текущую порчу: искусственная row-only модификация правильно вызвала отказ strict import.

## Что изменится и зачем

Каждое изменение модели имеет явную политику чтения истории, старых envelope, export/import и поведения старого клиента.

## Шаги реализации

1. Развести storage schema version, export format version, event/result codec version и поколение данных. Generation обозначает восстановление/замену истории, а не автоматически любую новую колонку.
2. Для типов изменения составить таблицу: добавление необязательного поля, новое событие/сущность, переименование поля, изменение смысла. Выбрать upcast/codec либо атомарную миграцию истории; смешивать их без правила нельзя.
3. Описать совместимость persisted operation result и hash исходного envelope. Миграция не должна сделать прежний повтор новой командой или лишить возможности узнать завершённый результат.
4. Добавить handshake/protocol capability для snapshot/stream и понятный режим несовместимого web/CLI. Сохранить локальные pending/drafts; не отправлять их молча как новый формат.
5. Готовить историческую fixture с create/edit/comments/checklist, sync, undo, noop, rejection и batch. Проверять upgrade → export → strict import → replay.
6. Связать preflight релиза с версией, а rollback — с совместимостью данных и границей открытия записи. Не откатывать старый код на необратимо новый формат после рабочих записей.
7. Ввести короткий checklist для каждой новой доменной сущности. Настройки оформления из плана 25 должны пройти его, если становятся общей синхронизируемой сущностью.

## Проверки

- [ ] Предыдущая база с историей проходит миграцию и strict round-trip без переписывания смысла старых действий.
- [ ] Старый pending envelope получает стабильный исход или явный несовместимый протокол; его текст не удаляется.
- [ ] Старый открытый web-клиент не применяет неизвестное событие как известное и не сообщает ложную синхронизацию.

## Критерий готовности

Есть документированная матрица эволюции и исполняемая fixture предыдущей версии; правила применены к первому реальному изменению формата.
