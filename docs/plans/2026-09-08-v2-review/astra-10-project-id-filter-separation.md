## Причина и наблюдаемое поведение

Допустимый ID проекта none совпадает со значением «без проекта», all — с фильтром всех проектов. Создание проходит, а запрос и элементы выбора трактуют реальную запись как служебное значение. none воспроизведён, аналогичный путь all установлен чтением кода.

## Что изменится и зачем

Любой допустимый сохранённый ID однозначно адресует проект. «Все» и «без проекта» выражаются отдельными признаками фильтра, а не специальными ID.

## Шаги реализации

1. В shared-модели ввести различимые состояния фильтра: все проекты, unassigned, конкретный projectId. Не менять идентификаторы уже сохранённых проектов.
2. В API определить точный параметр projectId и отдельный режим unassigned; описать запрет противоречивых комбинаций. Для старого project-параметра оставить явно описанный переходный разбор.
3. В URL и CLI обеспечить способ выбрать буквальный ID none/all. Обновить сериализацию фильтров и fingerprint страниц.
4. В dropdown использовать значения, не совпадающие с domain ID: например служебный tag и закодированный project tag. Применить во всех фильтрах и формах назначения проекта.
5. Проверить импорт/экспорт, task.sync, поиск и sidebar: они должны сохранять допустимые ID без скрытого переименования.
6. Обновить примеры и сообщения валидации; резервирование новых слов вместо исправления чтения рассматривать только как явно менее совместимую альтернативу.

## Проверки

Нет общего строкового пространства у служебного фильтра и ID; существующие записи доступны; исходный probe проходит.
