# TaskIndex v2: независимое ревью

Дата: 2026-09-08. Проверена редакция плана на 728 строк, SHA-256
`9d280f84f00de594ec9c87a07608e283ae759b66a05ba57abbd404ec8a86d8ff`,
на базе коммита `4b780e4`, worktree `worktree-v2-plan`.

Два отдельных агента получили чистый контекст. Первый прочитал весь план,
проверил контракты и существующее поведение. Второй проверил соразмерность
архитектуры, процесс разработки и восстановление. Координатор независимо
сверил выводы с текстом плана, кодом и первичными источниками.

Вывод: стек и продуктовый объем подходят одному владельцу с несколькими
агентами. Перечисленные технические исправления внесены в план; затем начата
и выполнена локальная реализация v2, проверенная ниже. Новая БД, брокер сообщений, очередь фоновых работ или другой UI
для этого не требуются. Исправление текста плана не означает, что будущая
реализация уже проверена.

## Детали, которые должны стать проверками реализации

- Любой окончательный успех без событий завершает pending. Это касается
  не только `existing` и `skipped:all`, но и повторного удаления комментария.
- Несколько событий одной операции должны иметь определенную границу
  завершения. Нельзя снимать весь оптимистичный эффект пакетного Undo
  после первого из нескольких событий.
- Версия источника должна действительно отражать порядок его изменений.
  Старый кеш, прочитанный позже, не становится более свежими данными.
  Момент наблюдения и ETag не доказывают хронологический порядок; неизвестная
  свежесть должна оставаться явно неизвестной. Явная правка с revision
  остается доступна. Непрозрачность ETag определена в
  [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.3).
- Undo предметных изменений не должен возвращать назад техническую отметку
  уже обработанной версии источника и тем самым снова допускать тот же
  отмененный импорт.
- Зафиксировать отдельные пакеты плагинов Better Auth и корректное строковое
  сравнение fractional-indexing. Сортировка через `localeCompare` здесь
  непригодна: это отмечено в
  [документации fractional-indexing](https://github.com/rocicorp/fractional-indexing#sorting).

## Принятые упрощения процесса

1. Один изолированный worktree для новой версии, те же шесть этапов и
   проверки. Отдельный worktree и PR для каждого строго последовательного
   этапа не нужны. Работающий `main` сохраняется; коммиты и публикация
   выполняются в пределах разрешения владельца.
2. Минимальный CLI и тонкий работающий экран появляются до завершения
   полного интерфейса. Ранний сценарий: агент создает и синхронизирует,
   SQLite фиксирует, SSE обновляет экран, владелец меняет задачу, повтор
   агента сохраняет решение владельца, исход оборванной операции выясняется
   по ее ID. Затем достраиваются команды и точное визуальное соответствие.

Сохранены согласованные optimistic UX, таблица чеклиста, `held + health`,
комментарии, история, активность, агентский digest и полный API/CLI.
Предложение хранить чеклист JSON не принято: текущая схема работоспособна,
ради этого изменения повторно проектировать ее не требуется.

## Реализация после ревью

В том же worktree реализованы общий слой команд и схем, сервер SQLite/Hono,
авторизация владельца и устойчивые идентичности агентов, полный API и CLI,
интерфейс со store/outbox/SSE, комментарии, история, активность, экспорт/импорт,
контейнер и процедуры резервирования. Новый интерфейс сопоставлен с сохранённым
эталоном: [снимки и сценарии](../reference/v2-validation/README.md).

Подтверждённые дефекты реализации исправлены до завершения:

- Одиночный конверт команды отделяется от payload общего reducer; проверены и
  одиночные команды, и пакеты через реальный HTTP-слой.
- Undo защищает ручную правку `originUrl`, собирает все конфликты, учитывает
  создание записи и промежуточные перестановки UNIQUE в одной транзакции.
- Импорт проверяет весь журнал, результаты операций, чеклист и итоговое
  состояние. База с агентами, авторизацией, операциями или пользовательскими
  настройками не считается пустой; без `--replace` её данные не удаляются.
- Сводка операции включает результат. Неуспешный command и успешный GET его
  сохранённого результата различаются в UI и CLI. Потеря ответа с 404/409
  не оставляет вечный outbox и не запускает новое изменение.
- SSE сразу отправляет служебный комментарий и открывает соединение даже без
  бэклога. Пакеты применяются полностью; no-event успех завершает pending.
- Пустая колонка корректно принимает перетаскивание мышью, касанием и
  клавиатурой; DragOverlay сохраняет видимость переносимой карточки.
- Drizzle получил согласованные baseline snapshot/journal; повторный generate
  не создаёт повторные CREATE TABLE. Сборка выпускает ожидаемые `.js` entrypoints.
- Nginx передаёт все нужные заголовки в SSE location; Better Auth использует
  перезаписанный proxy заголовок X-Real-IP. Runtime образ не содержит генератора
  миграций и остальных необязательных инструментов разработки.

### Что остаётся до рабочего запуска

1. Домен, выбранный VPS, S3 bucket/prefix и ссылки на секреты владельца.
   На этом окружении нужны сборка под архитектуру VPS, установка, TLS, проверка
   реплики и повтор drill. Linux/amd64 этим локальным прогоном не проверялся.
2. Физический телефон/Safari и настоящий passkey/Touch ID. Виртуальный Chromium
   подтверждает протокол и UI, но не работу конкретного устройства.
3. Просмотр владельцем сохранённого интерфейса и новых Activity/comments/history.
4. Подключение скилла и ключей в рабочие Claude Code и Codex, прогон из обеих
   реальных сред по `tests/e2e/agent-cycle.md`. Автоматический тест с двумя ключами
   не выдаётся за проверку физической сессии Claude Code.
5. Коммит по слову владельца и развёртывание на рабочем VPS. Локальное
   переключение на v2 в основной папке уже разрешено и выполнено, см. дополнение ниже.

Известный некритичный предел текущей сборки: основной JS chunk — около
298 KB gzip, Vite предупреждает о размере до сжатия. Предупреждение не скрыто;
это возможная последующая оптимизация загрузки, а не ошибка выполненных сценариев.
В полном dev-дереве npm audit также сообщает четыре moderate записи одной цепочки
Drizzle Kit → старый esbuild. [Advisory esbuild](https://github.com/evanw/esbuild/security/advisories/GHSA-67mh-4wv8-2f99)
касается его serve-режима; TaskIndex его не запускает, а runtime образ эту цепочку
не содержит. Downgrade через `npm audit fix --force` не применялся.

Рабочая `.wrangler/state`, основная ветка и её пользовательские изменения не
редактировались. Коммитов, push, merge, публикации на VPS и удаления worktree нет.
