# TaskIndex

Доска задач владельца. Агент читает свободно, пишет только по правилу ниже.
CLI `taskindex` печатает JSON. Флаги любой команды: `taskindex help task create`
(и так для каждой). Каталоги областей, направлений и меток: `taskindex context`.
Кто ты для сервера: `taskindex me`. Техника (задачи из источников, курсоры,
обрыв сети, коды) в `reference.md` рядом с этим файлом.

## Правило записи

1. Запись (`task create|update|save|move|archive|restore|sync`, `checklist *`,
   `project *`, `comment *`, `undo`, `batch`) только по просьбе владельца в
   этом разговоре. Находка без просьбы: сказать в чате, не писать.
2. Всегда два шага: показать точную карточку или точное изменение, дождаться
   отдельного «да». «Иди создай эту задачу» это просьба, не подтверждение.
   Комментарий показывается текстом целиком, как и всё остальное.
3. Владелец поправил показанное: показать исправленную версию, снова ждать
   «да». Несколько изменений: одним списком, одно «да» на весь список.
4. «Да» относится к последней показанной карточке. Нет «да»: ничего не
   записано.
5. «Выполни задачу X»: сделать работу, а изменения карточки (В работе,
   комментарий с результатом, Готово) показать одним списком в конце и
   записать после «да».
6. Сессия без сообщения владельца (крон, рутина, изолированный запуск):
   только чтение.
7. После записи одна строка: идентификатор, что изменилось, ссылка
   `$TASKINDEX_URL/?task=ID`.

Перед карточкой на создание проверить дубли: `taskindex tasks -q ТЕКСТ`.
Нашёлся похожий: показать его и спросить, нужна ли новая.

Карточка перед созданием:

```
Область: Агентство · Направление: Контент
Название: Проверить отчёт
Приоритет: P1 · Метки: деньги · Срок: 2026-09-15
Заметка: нет
Создаю?
```

Изменение: `Проверить отчёт: В работе → Готово. Закрываю?`
Комментарий: текст целиком, затем `Пишу в задачу «Проверить отчёт»?`

## Что куда

- **Области.** `agency` Агентство: всё по агентству. `development`
  Разработка: задачи по коду, направление называется как папка репозитория в
  `~/code`; направления нет — предложить завести вместе с задачей, одно «да»
  на оба. `personal` Личное: без направлений.
- **Направления агентства** выбирать по описаниям из `context`: Найм, Контент,
  Чатинг, Трафик, Финансы, Организационное. Деньги за найм это Найм с меткой
  `dengi`. Сомнение решает владелец: спросить, не угадывать.
- **Приоритет.** `p1` горит, `p2` обычная (по умолчанию), `p3` когда-нибудь.
  P1 ставится только словами владельца. Порядок карточек ручной, приоритет
  не сортирует.
- **Метки** только из каталога `context → labels`: `otvet` нужен ответ или
  решение владельца кому-то; `dengi` платёж, долг, финансовое решение;
  `5-min` делается за минуты; `lora`, `lily`, `ari` про модель. До 8.
  Новой метки нет: это правка кода, не команда.
- **Сроки и обязательства не придумывать.** Нет срока в словах владельца —
  нет срока в карточке. «Когда-нибудь» это P3 без срока.
- **`closes`**: слаг проблемы из `/OS/PROBLEMS.md`, если задача её
  закрывает. Завершение задачи проблему не снимает, это делает сессия /OS.
- **Статусы:** `todo` Очередь, `doing` В работе, `waiting` Жду
  (`--waiting-for` кого ждём, `--follow-up` дата возврата), `done` Готово.
- **Слова владельца.** «Оформи»: заполнить заметку и шаги у существующей
  задачи. «Продумай»: ответить в чате, писать после «ок». «Закрой»:
  `task move --status done`. «Убери»: `task archive`.
- **Агент не трогает:** focus и порядок на столе, оформление доски, поля,
  которые владелец правил руками (сервер откажет без
  `--confirm-owner-fields`; флаг ставить только когда владелец поручил
  именно это поле, он виден в «Активности»).

## «Что горит»

`taskindex digest` (`counts.p1`, `counts.otvet`), затем
`taskindex tasks --priority p1`, `taskindex tasks --label otvet`,
`taskindex tasks --today true` (срок или дата возврата не позже сегодня).
Ответ списком без повторов: направление, название, срок, чего ждём, почему
попало в список. Ничего не записывать.

## Шпаргалка

| Что | Команда |
|---|---|
| Каталоги | `taskindex context` |
| Состояние доски | `taskindex digest` |
| Найти | `taskindex tasks -q ТЕКСТ`; фильтры `--area`, `--status`, `--priority`, `--label`, `--project`, `--closes` |
| Прочитать | `taskindex task get ID` (даёт `revision`) |
| Создать | `taskindex task create --area agency --title … --priority p1 --labels dengi --due 2026-09-15 --note …`; направление `--project-id ID` |
| Изменить поля | `taskindex task update ID --base-revision N …` |
| Статус | `taskindex task move ID --base-revision N --status done` |
| Архив | `taskindex task archive ID --base-revision N` |
| Комментарий | `taskindex comment add ID --text …` |
| Направление | `taskindex project create --area development --name … --color … --description …` |
| Пакет | `taskindex batch --file commands.json` |

Перед `update`, `move`, `archive` прочитать `task get ID` и передать его
`revision` в `--base-revision`. Ответ `conflict` (код 3): перечитать
`current`, показать владельцу заново, свежую revision механически не
подставлять.

TaskIndex не отправляет сообщения, не переводит деньги и не меняет внешние
системы. Запись задачи об этом не означает выполнение.
